# ActiveSync on PHP 8.4 Implementation Plan (Phase 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `webtop-z-push` image runs Sonicle's released ActiveSync server on PHP 8.4 with Z-Push 2.7.7, built in `ns8-webtop` from Sonicle's package, our `composer.lock` and a small patch, and phones can hold a push request (Ping) longer than 60 s, with the phone sync tests passing unchanged.

**Architecture:** Same shape as Phase 1 (`webdav/`): `build-images.sh` runs `z-push/build.sh` in a builder container made from the runtime base image. It unpacks Sonicle's `webtop-eas-server-<version>.tgz`, checks Sonicle's composer files, drops the bundled `vendor/` (Z-Push 2.4.5 included) and dead code, puts our `composer.json`/`composer.lock` in place, applies `z-push/patches/*.patch` and runs `composer install`. Z-Push 2.7.7 arrives unmodified through a Composer `package` repository named `z-push/z-push`, so it lands at `vendor/z-push/z-push/src`, where Sonicle's code loads it. The tree goes into the `webtop-z-push` runtime image (PHP 8.4 + `imap`) and the `webtop-apache` image. Apache's FastCGI timeout for Z-Push is raised so a Ping can last as long as ActiveSync allows.

**Tech Stack:** buildah, `php:8.4.27-fpm-alpine`, `mlocati/php-extension-installer` 2.11.34, Composer 2.10.3, Z-Push 2.7.7, Robot Framework phone sync suites, phonesync helper (Python standard library).

**Spec:** `docs/superpowers/specs/2026-10-21-php84-dav-eas-fork-design.md`
**Previous phase:** `docs/superpowers/plans/2026-10-22-webdav-php84.md` (its `webdav/` directory is the model for `z-push/`)

## Global Constraints

- PHP 8.4, base image `docker.io/library/php:8.4.27-fpm-alpine` (Phase 1 decision; `imap` builds there). Fall back to 8.3 only if `imap` fails on 8.4.27.
- Z-Push 2.7.7 unmodified. Never patch Z-Push or other libraries; patches touch only Sonicle's code. A library bug gets a separate `NN-temporary-<library>-<issue>.patch`, listed in the README and reported upstream.
- Nothing from Sonicle's unreleased WT-1456 branch. Behaviour parity: folder ids and types, sync windows, item contents, user details unchanged. A phone that must be set up again or resyncs everything after the upgrade is a failure.
- The phone sync suites must pass unchanged; only `known-issue` cases may be skipped. Adding tests is allowed; editing existing assertions is not (except removing the `known-issue` tags of the Ping case this phase fixes).
- Library majors stay as Sonicle has them (guzzle moves to 7 as in Phase 1; lf4php 4, monolog 1, hassankhan/config 1, html2text 4, data-uri 0.2), unless PHP 8.4 or Composer's security-advisory block forces a move. Then use the lowest unblocked version and ledger it.
- Development and staging builds apply the same patches; a patch that does not apply fails the build with a message naming it.
- `z-push/LICENSE` is AGPL-3.0, with a notice in the README that the patches modify Sonicle's AGPL code (as in `webdav/`).
- PHP settings carry over from `main`: `zz-banner-grabbing.ini`, `zz-session-upload-progress.ini`, `zz-fpm-mitigations.ini`, `pm.max_requests = 1`, fpm `log_level = warning`. Pool sizes stay at 50/5/5/35, `memory_limit` 512M, fpm port 9001.

## Review Focus

- **Device state written by Z-Push 2.4.5 must load in 2.7.7:** no re-provisioning, no full resync, no duplicates. Pinned by `21_pre_upgrade` → update → `23_post_upgrade` in Task 5, and by CI's update scenario.
- **Constants defined twice:** Sonicle's `backend/wtimap/config.php` defines the `IMAP_*` constants, then Z-Push's own `backend/imap/config.php` defines them again. On PHP 7.3 that was a hidden Notice; on PHP 8 it is a Warning on every mail request. The values must stay Sonicle's (first define wins) and the warnings must go away. Pinned in Task 3 by a smoke check, and in Task 5 by reviewing the log at WARN level.
- **Missing extensions:** a PHP extension that the 7.3 image had and Z-Push 2.7.7 or Sonicle calls, missing on 8.4. That would be a fatal error on a rarely used path, such as MIME or iconv on a mail with an odd charset. Pinned in Task 3 (the `php -m` list of the new image includes every module of the old one) and Task 5 (rich mail sync).
- **WebTop Devices panel parsing:** the panel parses `z-push-admin` 2.7.7 output (`-a list`, `-a lastsync`, `-a list -d -u`), which may differ in format. Pinned by `60_devices_panel` in Task 5.
- **Long Ping through the NS8 proxy:** real phones reach Apache through Traefik, so a Ping longer than 60 s must also survive Traefik. Pinned in Task 2 by a test through `https://127.0.0.1` with the WebTop host name.
