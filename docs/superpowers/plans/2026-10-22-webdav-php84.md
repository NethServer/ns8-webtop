# WebDAV on PHP 8.4 Implementation Plan (Phase 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `webtop-webdav` image runs Sonicle's released WebDAV server on PHP 8.4 with sabre/dav 4.7.x, built in `ns8-webtop` from Sonicle's package, our `composer.lock` and a small patch, with the phone sync tests passing unchanged.

**Architecture:** `build-images.sh` takes Sonicle's `webtop-dav-server-<version>.tgz` as today, drops its committed `vendor/`, puts our `webdav/composer.json` + `composer.lock` in place, applies `webdav/patches/*.patch` in order, and runs `composer install` in a pinned Composer builder container. The resulting tree is copied into the PHP 8.4 runtime image and into the Apache image (Apache maps `/webtop-dav/` onto the same paths). `prep-sources` and the Maven build stay untouched.

**Tech Stack:** buildah, official `php:8.4-fpm` images, Composer 2, sabre/dav 4.7, Robot Framework phone sync suites.

**Spec:** `docs/superpowers/specs/2026-10-21-php84-dav-eas-fork-design.md`

## Global Constraints

- PHP 8.4 (fall back to 8.3 only if the Task 1 spike shows `imap` cannot be built for 8.4; that choice is shared with Phase 2).
- sabre/dav latest 4.7.x (4.7.1 today) with the sabre/* versions it requires; other library majors stay as Sonicle has them (guzzle 6, monolog 1, lf4php 4, hassankhan/config 1) unless PHP 8.4 forces a move.
- Never patch sabre or other libraries; patches touch only Sonicle's code. A library bug gets a separate, clearly named temporary patch file, listed in the README and reported upstream.
- Behaviour parity: phones must not notice. The phone sync suites must pass unchanged (only `known-issue` cases may be skipped).
- Development and staging builds apply the same patches; a patch that does not apply fails the build with a message naming it.
- `webdav/LICENSE` is AGPL-3.0 with a notice that the patches modify Sonicle's AGPL code.
- Existing PHP settings carry over: `zz-banner-grabbing.ini`, `zz-session-upload-progress.ini`, fpm pool sizes and `pm.max_requests`.
- All work on branch `test/phone-sync-e2e` (PR #328, stays draft).
- Sonicle input: the `wt-5.35.7` package (`webtop5-build/VERSION`). For local work, build it without Maven by `tar -C <sonicle-webtop/webtop-dav-server checkout at tag wt-5.35.7>/src -czf webtop5-build/webtop-dav-server-wt-5.35.7.tgz .` (packages are byte-identical to `src/`); CI gets it from its cache as today.
- Develop on rl1 `webtop5` by updating it to the branch image published by CI (`ghcr.io/nethserver/webtop:<branch name with / replaced by ->`, e.g. `test-phone-sync-e2e`, as shown by `Publish images`); recreate the robot venv and root self-SSH key there for the session and remove them at the end. Never run install/update suites on rl1.

## Review Focus

- A backend value of the wrong type (null etag, int size, missing displayname) must not turn into a PHP TypeError under sabre 4 strict types: the phone keeps syncing. Pinned in Task 4 Step 3 (sparse items created in WebTop and synced) and Task 5 (no `TypeError` in the logs).
- A WebTop REST redirect must not crash the DAV server (the old bundle missed `GuzzleHttp\Psr7\UriComparator`). Pinned in Task 2 (class present in the built tree).
- Deprecation notices from PHP 8.4 must not flood production logs. Pinned in Task 5 (no `Deprecated:` lines in the webdav log).
- `/.well-known/caldav` and `/.well-known/carddav` keep redirecting through Apache with the new tree. Pinned by the existing discovery tests.
- A Sonicle release whose files moved must fail the build clearly, not ship unpatched code. Pinned in Task 3.

## File Structure

| File | Responsibility |
|---|---|
| `webdav/composer.json`, `webdav/composer.lock` | dependency set for the built server (Sonicle's autoload sections kept as-is) |
| `webdav/patches/NN-*.patch` | our changes to Sonicle's code, one purpose each |
| `webdav/build.sh` | runs inside the builder container: unpack, check Sonicle's composer files, drop vendor, overlay, patch, `composer install` |
| `webdav/sonicle-composer.sha256` | recorded hashes of Sonicle's `composer.json` / `composer.lock` the overlay replaces |
| `webdav/check-tree.sh` | asserts library versions, required files and `php -l` on a built tree |
| `webdav/README.md`, `webdav/LICENSE` | refresh procedure; AGPL-3.0 notice |
| `build-images.sh` | builder step + PHP 8.4 runtime for `webtop-webdav`; Apache image gets the built tree |
| `tests/85_php_logs.robot` | no PHP fatal/uncaught/deprecation lines from webdav (and later z-push) during the run |

**Interfaces:**

- Produces: `webdav/build.sh <sonicle.tgz> <out-dir>`, run by `build-images.sh` in a container from the chosen `php:8.4-fpm` image with the pinned `composer` binary, `webdav/` and `webtop5-build/` mounted read-only and a host output directory mounted read-write.
